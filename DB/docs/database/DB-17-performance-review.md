# DB-17 — Final Indexing + Performance Review

## Scope

DB-17 is the final database indexing/performance gate for the supplied DB prompt sequence. The
review covers DB-02 through DB-16 without rewriting approved migration history.

## Corrections implemented

### Required partial indexes

- `skills(user_id, is_active)` → partial index with `WHERE is_active = true`.
- `notifications(user_id, is_read)` → partial index with `WHERE is_read = false`.

### Required vector completion

The earlier DB-16 implementation left vector dimensions unspecified. Final authority review found
that Database Constitution §46 explicitly fixes `text-embedding-3-small` at **1536 dimensions**.
Therefore the final forward-only migration changes both embedding columns to `vector(1536)` and
adds HNSW indexes using `vector_cosine_ops`:

- `skills_embedding_hnsw_idx`
- `profiles_embedding_hnsw_idx`

No earlier migration was rewritten.

## Required Specification §4.2 indexes

The final schema retains/implements:

- `profiles(user_id)` UNIQUE
- `profiles(reputation_score DESC)`
- `profiles(last_active_at)`
- `skills(search_vector)` GIN
- `skills(user_id, is_active)` partial
- `skills(category_id, is_active)` composite
- `transactions(initiator_id, status)`
- `transactions(provider_id, status)`
- `transactions(confirmation_deadline)`
- `skill_points_ledger(user_id, created_at DESC)`
- `messages(conversation_id, sent_at)`
- `notifications(user_id, is_read)` partial
- `documents(user_id, status)`
- `user_badges(user_id)`

Additional relationship/status indexes were reviewed and retained where they provide distinct
access paths.

## Financial integrity review

The ledger remains append-only at the public privilege boundary, keeps positive amounts and
non-negative balance snapshots, and synchronizes `profiles.skill_points` through the approved
trigger. Transactions retain participant, points, idempotency, status, deadline and completion
consistency constraints.

The executable integration suite covers valid ledger writes, invalid snapshots, overdrafts,
transaction invariants, duplicate ratings, FKs and related constraints.

## FTS review

DB-14 uses a generated `tsvector` projection over skill title/description and a GIN index. The
integration suite verifies initial generation and regeneration after source-text updates.

## pgvector review

DB-16 installs pgvector and stores nullable embeddings directly on `skills` and `profiles`. The
higher-authority Database Constitution supplies the 1536 dimension. DB-17 completes the dimension
and adds HNSW cosine indexes. The integration suite verifies extension availability, dimension,
index definitions and vector storage.

## Performance review boundary

The supplied environment has no production dataset or live PostgreSQL server, so no fabricated
latency/throughput figures are reported. The release includes the exact SQL integration tests and
index assertions needed for live verification. `EXPLAIN ANALYZE` remains a deployment-environment
measurement rather than an invented number.
